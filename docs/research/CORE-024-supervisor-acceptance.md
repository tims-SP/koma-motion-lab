# CORE-024：已得到透明图，按用途分别验收

日期：2026-10-30。执行：mcode 0.7.2；监工、独立像素核对及黑底视觉检查：Codex。

## 结论

当前有可用的抠图预览。侧脸 C 的 W245 版本保留原图 RGB，仅将与画布边缘连通的近白背景设为透明；没有重画角色。它可以用于摆放和合成试验，但耳尖、发丝有细白边与硬边，不能标为最终贴图。

更可靠的结构来源是原始 Aka PSD：62 个原生 RGBA 叶图层已完整导出，包括耳朵、脸、眼白、眼球、高光、嘴部、发束和阴影。这能直接提供前视部件与原生透明度；生成侧脸并未因此获得62个匹配的语义图层。

原图、PSD、INX、VRM、前序候选图、相机及依赖锁等14个受保护文件的 SHA256 均未变化。机器核对见 `experiments/reference-factory/evidence/core024-2026-10-30/`。

## 可复现方式

在 `experiments/reference-factory` 内，已有锁定依赖并运行 `prepare.py` 后，执行 `python native_layers.py`。它重新核对 PSD 哈希，导出 `out/core024/native-v2/`；CI 将此目录的媒体随既有证据 ZIP 放入 Draft Release，源代码仓库仍只保存文本。

本地侧脸比较执行 `python cutout_white_canvas.py`。需要本地原始 C 与透明编辑文件的固定哈希，不会在 CI 中隐式生成、下载或请求 AI 图像。输出在 `out/core024/white-canvas/`。

## 实际限制与下一步

PSD 单独导出的叶图层没有烘焙 multiply、opacity、mask 或 clipping；使用者应按记录的边界、层序与混合模式还原。强制透明合成的后发阴影存在外溢，这是部件组装需要处理的实际问题，不能当作已修好的 rig。完整前视 UV、连续转头、背面补全和360°均未验收。

本轮 rembg CPU 环境安装停在网络审批取消，没有完成模型安装或推理；不得报告为模型抠图成功。此前官方 See-through 的一次真实请求因匿名 GPU 配额失败，未取得语义 PSD；本轮没有绕过配额重试。

后续主线应使用这62层做源部件约束，将侧脸作为轮廓/遮挡参考，逐部件验证映射和遮挡。W245 解决的是当前“能否得到透明 PNG”，没有解决自动拆层和转面缺失内容。
