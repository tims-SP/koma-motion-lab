# MVP-008 — 动态水平 360° 联合动作（同一 TS 角色）

## 任务定位

静态原型 MVP-007 已经通过指定 12 部件/四关键方向/固定姿势的 360° 技术验收。此文档定义其后的 **动态联合验证**；不制作新角色，不引入复杂 Spine/Live2D 导入器，不重做成熟独立算法。

**目标**：同一简化角色在 8 秒内**持续转满水平 360°**，并同时执行右臂双骨 3D IK、头部独立视角 VDD、手部绕躯干从后到前、腿部简化次级运动。头部、手臂分别使用自己局部的视角求值，不能只给整个人物统一换一张图片。

## 本次实际改动（待当前 CI 确认）

- \`experiments/mvp002/src/integrated.ts\`：新增 \`renderDynamic360(yaw, frameIndex)\`，仍调用与静态同一 \`evaluate\` 与 \`artMesh\` / \`sample\` / \`registeredMaterial\` / \`solveIK\`。连续 yaw 与非静态姿势一起求值；传回真实 \`FrameTrace\` 和 \`pose\`（手、肘、肩、双脚位置及手相对躯干的局部深度）。
- \`src/qa/turn360-runtime.ts\`：动态帧记录实际 poseHash，保持每部件骨骼矩阵 / 视觉网格 / 素材和相机证据。
- \`scripts/render-dynamic360.ts\`：同一浏览器 192 帧逐帧截图 + 部件 ID pass + FFmpeg，输出 8 秒 MP4、16 关键阶段图板、8 个角度的 ID/depth/mask 和全帧 JSON/QA。
- \`.github/workflows/mvp008-dynamic360.yml\`：自动 TS 校验、Chromium/FFmpeg 真实渲染、20 天下载证据；即便结构 FAIL 仍保存文件，不可掩盖缺陷。

## 最低机器门禁 D01—D09

| 门禁 | 预期证据 |
|---|---|
| D01 同时运动中完成 0—360° | 全部 192 帧 yaw 与真实姿势均在变 |
| D02 同姿势同时间 0/360 周期 | 两张独立 PNG 像素一致 |
| D03 头局部偏转 | 独立头部 yaw 范围非零且可控 |
| D04 双骨 IK | 3D 手末端逼近目标，手移动有一定幅度 |
| D05 手部前后穿越 | 使用**身体局部坐标**深度，不以世界 z 的正负冒充 |
| D06 双脚高度 | 根部 Y 固定，仅证明高度，不证明真实地面接触 |
| D07 动态 Anchor/VDD | 根据每帧局部骨骼矩阵和相机矩阵独立复算 |
| D08 完整性/网格/裁切 | 真实部件 ID pass；全部 192 帧编码可解码 |
| D09 时间连续 | 解码最终 MP4，比较逐帧亮度变化，定位异常峰值 |

**原则**：D01—D09 全 PASS 最多是 \`PASS_STRUCTURE_PENDING_VISUAL\`；并不等于完整动态人物已经合格，特别是姿态依赖的遮挡、骨骼投影缩短、全身脚步 IK、复杂透明图层仍有独立缺口。

### 额外必须补的姿态相关可视验收

需要对真正发生手部前后穿越的帧，使用隔离手臂/躯干 Alpha mask 与最终 ID 合成像素，检查该处是否正确遮挡；至少有正面/背面对应真实重叠像素，不能出现 0 sample 的假 PASS。只证明深度 \`localZ\` 穿越不够。
