# ADR-002 — 2.75D Anime Studio: locked research architecture after CORE-020

**Date:** 2026-10-30  
**Status:** ARCHITECTURE SELECTED FOR RESEARCH, NOT PRODUCTION QUALITY ACCEPTED  
**Repositories:** `tims-SP/koma-motion-lab` experiments and QA; `tims-SP/koma-motion` production body (leave untouched until production gates pass).  
**Context:** Personal, noncommercial use. No source/binary artwork committed to Git; references and research metadata in Git, private downloadable media in GitHub Actions artifacts / owner-only Draft Releases.

## Decision in one sentence

Reuse **the actual native INX/PSD layered 2D character, original immutable ArtMesh topology/UV/parameter rig**, augment specific head/ear/hair/face parts with shallow real 3D surfaces and **independent view-conditioned authored skins/UVs**, then render deterministic video through **TypeScript/Three.js/WebGL2 with Chromium and FFmpeg**. Use **Inochi2D official D implementation as reference**, **Inox2D Rust/OpenGL for experimental parsing and source-reference validation**, Python/OpenCV/NumPy for asset registration/QA, and Agent/GitHub Actions for automation and inspection. Godot/Blender are optional offline authoring/verification utilities, not the primary runtime.

## Why this architecture

- Pure whole-image crossfades and optical flow fail real anime turning (observed CORE-013 and CORE-014 doubled eyes/ears and false hair/cheek overlays).
- A real Z buffer, part meshes and view-conditioned skin remove some visual ghosting (CORE-015) but *do not invent painted side or back*; unreliably projected white ear fur/face deforms (CORE-015/016).
- The actual original Inochi2D ear components are **57/59 ArtMesh vertices, 89/93 triangles**, with real original TGA and UV including UV outside [0,1]; preserve native UV untouched.
- Authentic source data contains 76 ArtMeshes, 3,427 native vertices / 5,353 native triangles for full Aka; originally modeled as a layered 2D puppet, NOT complete closed 3D.
- Native original Head:: Yaw-Pitch **external input** is min [-1,-1], max [1,1], defaults [0,0], nine normalized X control points / three Y. Do NOT confuse external input `(0.5,0.5)` with internal `(0.5,0.5)`: it maps to normalized `(0.75,0.75)`. This was a consequential miscomparison in CORE-017–019 and corrected in CORE-020.
- CORE-020: 17 actual native OpenGL 720×880 ear-only GPU source frames, H264 movie encoded & decoded, and nine same-pose CPU sampled frames. One common offset (-1,0) fit only to the first sample gives silhouette IoU 0.9403 at external yaw .5, 0.8933 at .75 and 0.8452 at 1.0, with sampled color MAE 8.40, 10.61 and 12.59 /255 respectively. **These are not source default [0,0] parity and not certified pixel-identical.**

| Binding | Source front UV0 immutable; newly registered view UV1..N + face/eye/hair/ear visibility masks/depth maps | A part-specific surface correspondence must be established for each view; no global image crossfade |

## Texture/mesh data design (proposed contract, not implemented)

A `CharacterPart` carries `originalNodeUuid`, `parentUuid`, `originalMesh2D(vertices, faces)`, `originalUV0`, `originalTextureId`, `sourceParamBindings`, a deformable shallow `surface3D`, plus view-specific `{nominalYawDeg, sourceImageHash, calibratedCamera, uv, rgbaParts, occlusionMask, hiddenUnderpainting, approvalStatus}` entries. The engine must evaluate original mesh pose first, then lift corresponding vertices into geometry without changing front UV and render angle-conditioned skins, preserving original front.

**Mature references:** Inochi2D SDK https://github.com/Inochi2D/inochi2d ; Inox2D experimental Rust port https://github.com/Inochi2D/inox2d ; Eurographics 2026 ModelSheetTo3D https://github.com/hjyoon02/ModelSheetTo3D (view angles, separate decals, independent surface mapping; NOT a drop-in real-time renderer).

- **CANDIDATE_+90:** GPT generated separate head profile, no approved layer separation, no camera/landmark calibration, no 3D UV.

- **CANDIDATE_NEAR_FRONT_+45:** provisional uncalibrated GPT near-front reference only, not source registered.

- Reference/composite existence never counts as `PRODUCTION_ACCEPTED`.

## Minimum production gate, in strict order

1. **P0 Correct default 2D source parity:** capture actual native external `HeadYaw=(0,0)` and compare same-stage source ArtMeshes, masks, transforms and native GL texture sampling. Gate includes unique per-part visual audits and source pixels; exact pixel identity may differ across backends due to antialias and must be expressed as audited numerical tolerances, not assumed. Test other raw inputs including `(1,0)`.
2. **P1 Canonical geometry:** create anatomically plausible 3D head, ear panels and layered hair with 0° silhouette and ear roots matched, stable front art, Z test. Separate independently authored back/side from front.
3. **P2 Multi-view painting:** start with genuine +90° and 180° independent images, segment per part and paint hidden surfaces, validate against Aka original identity; then create +/-45°, +/-90° and +/-135° (orientation convention fixed and verified).
4. **P3 Per-view UV/rig correspondence:** preserve all original frontal UVs; align and test new view-specific UV for eyes/face/ears/front/back hair, with coherent occlusion and seamless transitions.
5. **P4 MP4 acceptance:** render in one verified WebGL environment, encode real full-head 0→180→360 and decode actual frames. Reject face ghosts, ear-thickness collapse, impossible side faces, hair-root seams, backside face appearance, white/magenta missing art, flicker and temporal pops. Preserve camera/pose provenance and image hashes.
6. **P5 Automation/generalization:** Agent generates manifests/segmentation/proposals, runs unit/render QA, proposes fixes and releases own review artifacts. Never auto-promote unreviewed generated art into production.

**Hard acceptance rule:** no completed 360° high-quality anime character is claimed until full appearance, original front fidelity, multi-view identity and *actual decoded final video* all pass. A 3D rotating proxy, a CI-success flag, or a printed “UV / frames” label inside an AI image is never sufficient.
