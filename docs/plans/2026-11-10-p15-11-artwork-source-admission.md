# P15-11 · 多视角独立原画候选与身份准入

日期：2026-11-10
角色：`p0_character_001`
仓库：`tims-SP/koma-motion-lab`
执行通道：ChatGPT → Supabase → chatgpt-vps-bridge-worker → VPS

## 本轮目标

补充 57.5° 与 60° 的独立视角原画，作为 P15-10 55°–65° ArtMesh 分层变形的候选关键帧。原始 45° 角色及已登记 65° 候选分别用于检查角色身份、朝向、五官、发束、发夹物理侧别和构图一致性。每张原画在分层或引入渲染关键帧前必须独立通过艺术质量准入。

## 来源与产出

本轮已连接 Hugging Face 账户实际调用 Qwen-Image-Edit-2511，选用 `Multiple-Angles` 和 `Fal-Multiple-Angles` 适配器。在 45°、65° 原画源和 P5 55° 几何参考上进行不同方案的生成。所有输出保存为单独 1024×1024 RGB PNG，生成参数、参考角度、Git 图片对象 SHA 与源 PNG SHA 记录在：

`experiments/gif-multiview-keyparts-mvp/metadata/p15-11-source-candidates.json`

共保存四份绘制候选。真实视觉审查发现：

| 标称角度 | 生成路线 | 主要观察 |
|---|---|---|
| 57.5° | 45°+65° 双参考 | 接近侧脸，远眼缺失，发夹位置不符合原始身份 |
| 57.5° | 双参考另一姿态 | 朝向与原画相反 |
| 57.5° | 45° 单参考 | 朝向正确，但实际姿态接近全侧脸，远眼不可见 |
| 60° | 65° 单参考回转 | 头部姿态回到近正面，可见眼缺失虹膜/眼白纹理 |

每份候选已经通过真实来源哈希和 1024 RGB 尺寸验收，但**独立原画艺术准入为 0/4**。这不是脚本生成失败，而是关键帧解剖角度与身份连续性尚未达到要求。仍沿用 P15-10 已验证的 55° 几何与 65° 绘制参考，不将这些候选混入当前生产基线。

## 透明分层处理

复用 `rembg isnet-anime` 的 CPU 透明抠图，为全部四份候选生成单独的 1024×1024 RGBA PNG。针对每份 PNG 保存像素覆盖面积、部分透明像素、边缘、输入 SHA 与输出 SHA。透明抠图通过仅证明 RGB 前景隔离可复现；它不证明原画视角、五官或隐藏补绘的真实性，也不代表产生了 13 张独立绘制的语义部件。

当前正式语义资产合同仍为：同一原始人物、源角度真实可复核、发夹物理左右一致、远眼近眼有真实笔触和遮挡关系、13 个独立 ArtMesh 部件及不可见区域补绘。

## 后续重点

下一轮 P15-12 首先固定角色的真实 45°/65°/90° 相机方位和发夹物理侧别，建立数值化脸部 3D Anchor 与可见性示例，再以 **双眼可见且转向正确** 的实际绘画生成或分部件重绘 57.5°、60° 原画。对每个角度分别校验五官与发夹的解剖位置。确认关键原画后，再按独立原画层生成 13 个 RGBA 部件、隐藏补绘及跨视角笔触对应，使用与渲染输入不同的留出角做 IoU/面积/视觉质量测试。

**阶段结论：** 多账户图像编辑、原画 SHA 导入、透明抠图、HTML 审查与自动化源校验均已跑通；正确的 57.5°/60° 绘制源仍需继续创作。正式画质结果以多视角独立原画和解剖验证为准。
