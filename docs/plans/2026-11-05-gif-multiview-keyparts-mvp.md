## 二、两条直接生成通道

### A. 整头角度 GIF

生成 `head-turn-8view.gif`：按 `yaw000,045,090,135,180,225,270,315` 顺序，每帧是同一完整角色头肩像，一个角度一个静止关键帧。固定相机距离和脸部定位，允许器官随头部旋转产生真实遮挡。每帧标签写入外部 JSON 而非绘制到像素中。

产物：8 帧 GIF + 解码图片 `whole/yawNNN.png` + `whole/frames.json`，用作身份与角度参考。

### B. 直接生成透明部件 GIF（主要 MVP）

**每帧只包含一个指定关键部件**，独立绘制在透明背景上。不是先生成整图，再程序裁切。每一角度独立制作一组、按以下固定部件顺序分成三个短 GIF，降低逐帧画质和语义混淆风险：

| 组 | 逐帧部件 ID，顺序必须固定 | 每视角帧数 |
|---|---|---:|
| `face` | `face.skin`, `eye.near`, `nose`, `mouth`, `ear.near` | 5 |
| `hair` | `hair.front`, `hair.side`, `hair.back` | 3 |
| `identity` | `hair.ahoge`, `hair.clip.cross_gold` | 2 |

首轮角度 `yaw000`、`yaw045`、`yaw090`。共 **9 个透明部件 GIF、30 个独立图层帧**；加上整头 8 视角 GIF，共 **10 个 GIF**。`0°` 仅先制作 `face` 组 5 帧作为首轮可行性门禁，再扩展到 30 个登记槽。后续全周扩展时，近远耳／眼需绑定角色物理左、右 ID，以视角显隐映射。

固定语义局部生成方式：

- 参考输入：批准 P0 身份母图 + 对应 `whole/yawNNN.png` + 本组部件帧序列表。
- 帧号仅对应一个语义部件，画面不含其他角色器官、标签、表格、分割线。
- 每帧相同 `1024×1024` **全局定位画布**。部件留在整头中的原本坐标，保持形体比例、纹理和色彩；不能把每个鼻子、眼睛等单独缩放到占满画面。
- 输出背景是真实透明，角落 alpha 为 0；不能将白底或棋盘格绘制为图像。
- GIF 帧使用 restore-to-background/disposal=2 等可靠逐帧清场策略，确保切换部件时前一帧像素不残留。
- 对于本视角本来被遮挡的部件：给出 `visibility=hidden` 的可见性元数据，并优先生成用于形变的完整补绘几何；实际渲染只显示可见部分。
- 同一个物理发夹维持同侧、相同件数和角度变化；单根呆毛的根部、耳根和眼鼻相对结构必须跨角度一致。

### C. 从 GIF 提取可生产资产

对每个 GIF 逐帧解码，以 `yawNNN/<semanticId>.png` 保存一张一部件图片，并在 `parts.json` 登记 `frameIndex`、`semanticId`、`yawDeg`、`sourceGifSha256`、`frameSha256`、`visibility`、`bbox`、`anchors`、`depthOrder`、`creator` 和 `alphaQuality`。

GIF89a 是调色板图像，最多 256 色／帧，透明使用一个调色板索引，属于**二值透明**，不携带 PNG 的 0～255 半透明边缘。为保证画质：

1. 如果图像生成器同时提供原生 RGBA PNG 帧，将它作为正式生产资产，GIF 用于一致性、帧 ID 和快速预览。
2. 仅提供 GIF 时，可以从每帧提取二值 alpha PNG 验证可用性，再利用同一身份与视角条件重生成/修整 **RGBA 半透明边缘**；检查对深色、浅色两种背景的边缘效果。
3. 仅在部件生成失败或不可分离时，用 [See-through](https://github.com/shitagaki-lab/see-through) 进行局部图层恢复、被遮挡像素补绘，而不是所有原画的强制中转。

## 三、严格 MVP 步骤与门禁

| ID | 执行项 | 验收与输出 |
|---|---|---|
| T00 | 定位并校验已批准 P0 身份板／hero PNG SHA，生成器参考绑定 | `identity-lock.json` 包含真实文件路径、源 SHA、角色物理左右映射 |
| T01 | 整头 8 角度一致性 GIF | 8 个唯一角度帧、同一角色、发夹方向稳定、正/侧/背结构可见；`whole/*.png` |
| T02-A | **0° face 组 5 帧直接透明 GIF** | 每帧恰一个部件、角落透明、GIF disposal 正确、裁解 5 张完整画布 PNG、与身份母图坐标匹配；此项作为生成能力判定 |
| T02-B | 45°/90° face 与 0°/45°/90° hair、identity 透明 GIF | 累计 9 个语义 GIF，30 张逐部件 PNG，跨角度可见性正确、同部件身份一致 |
| T03 | 逐帧检验与 RGBA 边缘生产化 | 每部件 SHA、像素/alpha/bbox、原始全局坐标、语义 ID、非共线锚点、遮挡注册，层叠重建视角基准 |
| T04 | HTML 复用原有 Cubism/VDD 跨视角接口，建立 P0 角色 adapter | 0°→90° 逐部件变化与动态遮挡；22.5°/67.5° 留出角截图，消除五官/发束双重曝光，保留工程 QA 与人工视觉验收 |
| T05 | 完整 Demo 打包及持久化 | 10 个 GIF、8 张整头角度图、30 张部件图、manifest JSON、HTML、留出角图像、Chromium 测试报告、源哈希 |

MVP 先证明 **T02-A 单组透明直生成可用**，不需要等待全 30 图层。若其像素外形、角落 alpha、单部件隔离、角色位置和 GIF 帧数符合标准，紧接着批量执行其余组并进入 HTML。

验收图片必须由实际生成模型返回，再对实际文件解码检查；程序制作的合成几何测试只验证解析和渲染器，不计入生成能力。对 T04 的质量阈值先使用留出视角轮廓 IoU≥0.90、轮廓面积偏差≤8% 作为参考门槛，最终视觉以角色身份、轮廓、眼鼻、发夹、发丝遮挡无重影为准。

## 四、图层生成提示词规范（直接逐帧）

主提示：

> 使用提供的已批准角色 `p0_character_001` 身份参考图和同角色视角参考，输出一组日本动画风格的透明部件关键帧 GIF。头部角度固定为 `{yawDeg}`，画布为 1024×1024，全部帧保持同一个头部中心、像素坐标、比例、线稿和着色体系。帧次序必须严格是 `{partIds}`；一帧仅绘制一个对应的角色身体部件，其他所有像素完全透明，保留该部件在整头形象中的原始位置和尺寸。保持人物特征：藕粉短发、斜刘海、单根呆毛、角色左侧金色交叉发夹、紫粉眼、深蓝金边校服、酒红领结。描绘自然完整的部件轮廓和必要遮挡补绘，支持正面、45°、侧面的真实透视变化。所有帧是静态部件展示，按顺序播放，不绘制文本、编号、网格和白色背景。每帧播放后清理上一帧。

生成控制信息单独存 JSON，不把帧号写在图片上。请求生成透明背景，同时验证实际 GIF 是否有透明索引、alpha 边界和正确 disposal；生成模型可能不完全遵循，因此以产出文件实测而非提示词承诺判定。
