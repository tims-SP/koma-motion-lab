# P15-71 · 同视角前发语义图层真实可用性门禁

## 目标与基线
- 基线 Git b69f9d2，角色 p0_character_001，P15-56 同视角原画，P15-69 发夹和 P15-70 前额底图。
- 只处理前发与眉、眼、睫毛的真正语义分离。不能以颜色提取层冒充 ArtMesh，也不能将不同视角图层当作当前右向真值。

## 实际核查旧素材
- 核对 P15-20 45° 和 90° 独立前发透明图层，以及 P15-41 旧右侧候选的前发图层。
- 将这些图层按原始 1024×1024 坐标叠加到当前 P15-56 原画，输出放大图。
- 45° 叠加时发顶、眼睛、脸颊明显错位；90° 叠加时大块刘海盖住近眼；P15-41 来自不同候选。都不能作为相同视角同一底图的语义资产。
- P15-69 的色彩阈值前发仍含跨额头灰紫色线条，眼睫毛交界和真正发丝遮挡缺失。

## 模型实际执行
- 查到 Hugging Face 的 Premkishor0007/sam2-image-segmentation 运行中，支持 SAM2 点击式与自动分割。
- 生成当前原画的 512x512 裁切并成功上传到该空间。
- Gradio 队列调用 on_image_select 返回后端 generic failure，未输出分割。
- 进一步调用 handle_segment_everything 返回 ZeroGPU quota exceeded，未输出分割。
- VPS 没有现存 Hugging Face token，也没有已装本地 SAM 分割环境。此轮没有将失败误报为生成成功。

## 工程验收与结果
- 保存当前同视角原图、45° / 90° / P15-41 独立图层叠加、现有颜色层等实际可视对照。
- HTML 审查引用 P15-70 已生成的 0/9/18px 位移帧；没有伪称为新的 SAM2 图层。
- 测试核对来源 SHA、SAM2 失败、缺少同视角真值、禁止正式资产准入；Chromium 桌面及移动验证滑杆与全部图片。
- **正式 ArtMesh 视觉门禁 FAIL**。根本阻塞是缺少该视角真实语义前发与隐藏底层；SAM2 调用因后端报错和共享 GPU 配额受限。
- 正式 P0、ArtMesh、VDD 关键帧均未修改。
