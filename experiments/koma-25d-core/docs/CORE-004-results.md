## Fully sampled multi-view benchmark

Only **5 key views** are provided to interpolation, leaving **68 held-out
target angles** from the full 3D render. Scored RGB MAE over reference-or-
candidate subject pixels (background excluded). Smaller is better.

| Method | Mean MAE, 68 held-out views | Maximum MAE |
|---|---:|---:|
| Five-view RGB crossfade | **21.64** | 31.82 |
| Five-view Farneback flow warp | **28.27** | 40.92 |

The source anchor views match by construction, not because a reconstruction
algorithm has inferred the missing 3D geometry.

**Visual audit:** I directly examined the actual rendered 3-row contact
sheet from CI logs (real reference / crossfade / flow). Character images
are visually credible **in source reference 3D**. Mid-angles in both 2D
approximation methods exhibit doubled hair, arms, skirt and/or legs. Optical
flow makes many intermediate frames worse. Stop treating image blending
alone as a sufficient 2.5D anime representation.

## Thin 2D shell profile

Legacy GBot shell extrusion used a capped 0.75 world-depth; CORE-004 adds
a width-proportional depth option but still preserves source front UV and
front-only picture.

| Measure | Legacy | Proportional |
|---|---:|---:|
| 90-degree visible pixel coverage | 3.19% | **5.18%** |
| Relative 90-degree increase | — | **+62.5%** |
| Source-front view changed by added shell at 0 deg | 0% | 0% |

**Visual audit:** The actual profile contact sheet shows a larger side
strip, but no reliable anatomical shape: face/head hair/arms and chest
silhouette remain distorted or plain slab-like. At 135–180 degrees synthetic
checkerboard canary textures still appear. More thickness does NOT solve
multiview artwork reconstruction.

The front 0% result is comparison of SOURCE-FRONT-ONLY vs SHELL-ENABLED
from the *same Three.js renderer*, NOT pixel parity to native Godot.
